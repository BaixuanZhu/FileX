# M10: Windows Installer - Technical Design

## Architecture Overview

```
┌─────────────────────────────────────────────────────────┐
│                    NSIS Installer                        │
├─────────────────────────────────────────────────────────┤
│  1. Welcome & License                                    │
│  2. Installation Type (Install/Upgrade/Uninstall)        │
│  3. Directory Selection                                  │
│  4. Component Selection (Shortcuts, PATH)                │
│  5. Installation (Extract + Configure)                   │
│  6. Completion                                           │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│              Installation Directory                       │
│         %LOCALAPPDATA%\FileX                             │
├─────────────────────────────────────────────────────────┤
│  filex.exe              (wrapper script or binary)       │
│  filex.bat              (PATH resolution wrapper)        │
│  versions/                                              │
│    └── v0.2.0/          (versioned installation)        │
│        ├── filex.exe                                    │
│        └── ...                                          │
│  current -> versions/v0.2.0  (junction)                 │
│  uninstaller.exe                                        │
└─────────────────────────────────────────────────────────┘
```

## Component Breakdown

### 1. NSIS Script Structure

**File**: `installer/filex.nsi`

```
Sections:
- SecCore: Extract binaries and create directory structure
- SecPath: Add to PATH (using EnVar plugin)
- SecStartMenu: Create Start Menu shortcut
- SecDesktop: Create Desktop shortcut

Functions:
- .onInit: Check for existing installation
- InstallUpgrade: Handle upgrade scenario
- InstallFresh: Handle fresh installation
- Uninstall: Remove all components
```

### 2. PATH Management

**Plugin**: NSIS EnVar Plugin (`EnVar::AddToPath`, `EnVar::RemoveFromPath`)

**Behavior**:
- Add `%LOCALAPPDATA%\FileX` to user PATH during installation
- Remove from PATH during uninstallation
- Idempotent: check before adding/removing
- Broadcast `WM_SETTINGCHANGE` to notify running applications

**Fallback** (if EnVar unavailable):
- Manual registry manipulation via `WriteRegExpandStr`
- Read/modify/write `HKCU\Environment\PATH`
- Broadcast setting change via `SendMessage`

### 3. Directory Structure

The installer creates the same structure as the ZIP archive extraction:

```
%LOCALAPPDATA%\FileX\
├── filex.exe              # Actual binary (from archive)
├── filex.bat              # Wrapper for PATH resolution
├── current\               # Junction to active version
│   └── -> versions\v{version}\
├── versions\
│   └── v{version}\        # Versioned installation
│       ├── filex.exe
│       ├── README.md
│       └── ...
└── uninstaller.exe        # Generated by NSIS
```

**Wrapper Script** (`filex.bat`):
```batch
@echo off
"%~dp0current\filex.exe" %*
```

This allows the `current` junction to be switched by `filex upgrade` without updating PATH.

### 4. Upgrade Detection

**Registry Key**: `HKCU\Software\FileX\InstallPath`

**Logic**:
```
IF registry key exists:
    existing_path = read registry
    IF existing_path == current_install_path:
        # Same location, offer upgrade
        show_upgrade_dialog()
    ELSE:
        # Different location, offer uninstall first
        show_uninstall_prompt()
ELSE:
    # Fresh installation
    proceed_with_install()
```

**Upgrade Process**:
1. Stop any running FileX processes (optional, warn user)
2. Backup current `versions\` directory (optional)
3. Extract new version to `versions\v{new_version}\`
4. Switch `current` junction to new version
5. Update registry with new version info
6. Clean up old versions (keep last 3)

### 5. Uninstaller

**Location**: `%LOCALAPPDATA%\FileX\uninstaller.exe`

**Behavior**:
1. Show confirmation dialog
2. Remove from PATH
3. Delete installation directory
4. Remove shortcuts
5. Delete registry keys
6. Optional: keep `~/.filex/` config directory (checkbox)

### 6. Silent Installation

**Flags**:
- `/S` - Silent mode (no UI)
- `/D=<path>` - Custom installation directory

**Example**:
```
filex-setup.exe /S /D=D:\Tools\FileX
```

**Behavior**:
- Skip all dialogs
- Use default component selection
- Return exit code 0 on success, non-zero on failure

## Data Flow

### Installation Flow

```
User runs installer
    ↓
Check for existing installation (registry)
    ↓
[Existing found] → Show upgrade/uninstall dialog
[Fresh install] → Show welcome dialog
    ↓
User selects installation directory
    ↓
User selects components (PATH, shortcuts)
    ↓
Extract ZIP archive to versions\v{version}\
    ↓
Create current junction
    ↓
Install wrapper script to PATH directory
    ↓
Add to PATH (EnVar plugin)
    ↓
Create shortcuts (if selected)
    ↓
Write registry keys
    ↓
Show completion dialog
```

### Uninstallation Flow

```
User runs uninstaller
    ↓
Show confirmation dialog
    ↓
Remove from PATH (EnVar plugin)
    ↓
Delete installation directory
    ↓
Remove shortcuts
    ↓
Delete registry keys
    ↓
Show completion dialog
```

## Security Considerations

### 1. Code Signing

**Current**: Unsigned installer (warning shown by Windows SmartScreen)

**Future**: Sign with code signing certificate
- Use `signtool.exe` in CI/CD
- Requires purchasing certificate from CA
- Reduces SmartScreen warnings

### 2. PATH Injection Prevention

**Risk**: Malicious PATH manipulation could hijack commands

**Mitigation**:
- Only add to user PATH (not system PATH)
- Validate installation directory before adding
- Use absolute paths in wrapper script

### 3. Privilege Escalation

**Current**: User-level installation (no admin required)

**Future**: System-level installation (requires admin)
- Use `SetShellVarContext all` in NSIS
- Install to `%ProgramFiles%\FileX`
- Add to system PATH

## Alternatives Considered

### 1. MSI Installer

**Pros**:
- Enterprise deployment friendly
- Better for system-level installations
- Standard Windows installer format

**Cons**:
- More complex to create and maintain
- Requires WiX Toolset (steep learning curve)
- Overkill for user-level installation

**Decision**: Rejected for M10 (use NSIS instead)

### 2. Self-Extracting Archive (7-Zip SFX)

**Pros**:
- Simple to create
- No additional tools required

**Cons**:
- No PATH management
- No shortcut creation
- No uninstaller
- Poor user experience

**Decision**: Rejected (not a proper installer)

### 3. Chocolatey Package

**Pros**:
- Popular package manager for Windows
- Easy to maintain
- Handles PATH automatically

**Cons**:
- Requires Chocolatey installation
- Additional dependency for users
- Not a standalone installer

**Decision**: Complementary (can add in M11+), not a replacement
